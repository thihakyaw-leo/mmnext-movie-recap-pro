**ဤစစ်ဆေးမှုအတွင်း ပြုလုပ်ခဲ့သည့် ပြောင်းလဲမှု:** မူရင်းကုဒ်၊ စမ်းသပ်ဖိုင်များနှင့် ကိုးကားစီမံကိန်းများကို မပြင်ခဲ့ပါ။ ဤအစီရင်ခံစာဖိုင်ကိုသာ ဖန်တီး၊ ပြင်ဆင်ထားသည်။

## ကုဒ်နှင့် ဖိုင်ဘာသာစကားအကြောင်း

အရင်အစီရင်ခံစာ၏ ရှင်းလင်းချက်စာသားတွင် မြန်မာမဟုတ်သော ဘာသာစကား ပါဝင်သွားခဲ့သည်။ ယခုအစီရင်ခံစာ၏ ဖတ်ရှုရန်စာသားအားလုံးကို မြန်မာယူနီကုဒ်ဖြင့် ပြင်ဆင်ထားသည်။ စီမံကိန်း၏ အဓိကကုဒ်မှာ **Python** ဖြစ်ပြီး၊ ဤအစီရင်ခံစာဖိုင်မှာ **Markdown (`.md`)** ဖြစ်သည်။ ဖိုင်လမ်းကြောင်း၊ ကုဒ်အတွင်းရှိ အမည်များ၊ စမ်းသပ်ချက်၏ မူရင်းရလဒ်၊ API နှင့် မော်ဒယ်အမည်တို့ကို မှန်ကန်စွာ ရှာဖွေနိုင်ရန် မူရင်းအင်္ဂလိပ်အမည်အတိုင်း ထားထားသည်။

## အနှစ်ချုပ်

စီမံကိန်းတွင် PySide6 ကို အသုံးပြုထားသော Windows desktop application အခြေခံတည်ဆောက်ပုံ၊ အလုပ်လုပ်နေစဉ် မျက်နှာပြင်မရပ်စေရန် နောက်ခံ thread အသုံးပြုမှု၊ လုပ်ဆောင်မှုပုံစံများ ခွဲခြားထားမှု၊ မူရင်းစကားပြောစာသားနှင့် အချိန်အမှတ်များ မပြောင်းလဲစေရန် Exact Dubbing ကာကွယ်မှု၊ transcript အချိန်အမှတ် စစ်ဆေးမှုတို့ ရှိပြီး စမ်းသပ်ချက်များဖြင့် အချို့ကို ကာကွယ်ထားသည်။

သို့သော် လက်ရှိအခြေအနေကို အပြည့်အဝ ထုတ်လုပ်ရေးသုံး ရုပ်ရှင်အကျဉ်းချုပ်နှင့် အသံထပ်သွင်းရေးအက်ပ်ဟု မသတ်မှတ်နိုင်သေးပါ။ စက်တွင်းဗီဒီယိုမှ transcript ထုတ်ခြင်းအပြင် YouTube ခွဲခြမ်းစိတ်ဖြာမှုနှင့် ဒေါင်းလုဒ်လုပ်ခြင်း၊ ဘာသာပြန်ခြင်း၊ TTS အသံထုတ်ခြင်း၊ နောက်ဆုံးဗီဒီယိုတင်ဆက်ထုတ်လုပ်ခြင်းနှင့် အခြားလုပ်ဆောင်မှုပုံစံများ၏ အထွက်လုပ်ငန်းစဉ်များ အပြည့်အဝ ချိတ်ဆက်ပြီးစီးခြင်း မရှိသေးပါ။

အရေးအကြီးဆုံး တွေ့ရှိချက်မှာ အစစ်အမှန် (REAL) transcript ကို သိမ်းပြီးနောက် ပြန်ဖွင့်ရာတွင် လက်ဗွေတန်ဖိုး (fingerprint) မကိုက်ညီသည့် အမှားဖြစ်သည်။ လက်ဗွေတွက်ရာတွင် အသုံးပြုခဲ့သော ဆက်တင်များကို ပြန်ဖွင့်စစ်ဆေးရာ၌ ပြန်မသုံးသောကြောင့် ဖြစ်ကြောင်း စက်တွင်း စမ်းသပ်ဖိုင်တစ်ခုဖြင့် ထပ်မံအတည်ပြုခဲ့သည်။ ထို့အပြင် `pyproject.toml` ထဲရှိ ထည့်သွင်းဖြန့်ချိမည့် package စာရင်းတွင် လိုအပ်သော package နှစ်ခု မပါဝင်သေးပါ။

## စမ်းသပ်အတည်ပြုချက်များ

- စမ်းသပ်ချက်အပြည့်အစုံ — `.venv\Scripts\python.exe -m pytest tests -q --confcutdir=tests -p no:cacheprovider`။ ရလဒ်မှာ **၃၄၂ ခု အောင်မြင်၊ ၁ ခု ကျော်ထား၊ ၆၈.၆၂ စက္ကန့်** ဖြစ်သည်။
- ကျော်ထားသော စမ်းသပ်ချက်မှာ `tests/test_transcript_regressions.py:158` ရှိ ရွေးချယ်စရာ စစ်ဆေးမှုဖြစ်ပြီး၊ စမ်းသပ်ရန် မီဒီယာဖိုင်နှင့် စက်ထဲတွင် ကြိုတင်သိမ်းထားသော Whisper မော်ဒယ် လိုအပ်သည်။ ယခုစမ်းသပ်မှုတွင် ယင်းတို့ကို သတ်မှတ်မထားပါ။
- `QT_QPA_PLATFORM=offscreen .venv\Scripts\python.exe scripts\check_shell.py` ဖြင့် မျက်နှာပြင်အခွံကို စစ်ဆေးရာ အောင်မြင်သည်။ ပင်မဝင်းဒိုးနှင့် စာမျက်နှာ ၇ ခုကို ဖွင့်စစ်ပြီး သန့်ရှင်းစွာ ပိတ်နိုင်ခဲ့သည်။
- လက်တွေ့ပြန်စမ်းသပ်မှုတွင် `WhisperTranscriptAdapter` ဖြင့် fingerprint ဆက်တင်ပါဝင်သော transcript ဖိုင်တစ်ခု ထုတ်ပြီး `AppContext.open_transcript_from_job()` မှတစ်ဆင့် ပြန်ဖွင့်ရာ `ValueError: Fingerprint mismatch between artifact and current source` အမှားဖြင့် ပယ်ချခံရသည်။ ဖိုင်ထဲတွင် `fingerprint_settings` သိမ်းထားကြောင်းလည်း အတည်ပြုခဲ့သည်။
- စစ်ဆေးစာရင်းတွင် ယခင်က CPU ပေါ်တွင် `tiny.en` Whisper မော်ဒယ်ဖြင့် စမ်းသပ်မှုနှင့် REAL UI မှ နောက်ခံအလုပ်ဆောင်သူ၊ transcript ဇယားအထိ ချိတ်ဆက်မှု၊ Exact Dubbing မူရင်းစာကြောင်းများကို မပြောင်းလဲထားမှုတို့ အောင်မြင်ခဲ့ကြောင်း မှတ်တမ်းရှိသည်။ သို့သော် ယခုစစ်ဆေးမှု၏ စမ်းသပ်ချက်အပြည့်အစုံတွင် ရွေးချယ်စရာ မီဒီယာစမ်းသပ်ချက်ကို ကျော်ထားသဖြင့် ယခင်ရလဒ်များကို ယခုတစ်ကြိမ် ပြန်လည်စမ်းသပ်အတည်ပြုခဲ့ခြင်း မဟုတ်ပါ။
- NVIDIA `nvidia/nemotron-3.5-super-vl-120b-a12b` သို့ ဤစစ်ဆေးမှုမှ API တောင်းဆိုချက် မပို့ခဲ့ပါ။ ဤစက်၏ လုပ်ဆောင်မှုပတ်ဝန်းကျင်တွင် NVIDIA endpoint နှင့် API အထောက်အထားကို အသုံးပြုနိုင်သည့်ပုံစံဖြင့် မတွေ့ခဲ့ပါ။ ထို့ကြောင့် ဤအစီရင်ခံစာသည် Nemotron ၏ သုံးသပ်ချက်မဟုတ်ဘဲ စက်တွင်းကုဒ်၊ စမ်းသပ်ချက်နှင့် လက်တွေ့ပြန်စမ်းသပ်မှုတို့အပေါ် အခြေခံသည့် စစ်ဆေးချက်ဖြစ်သည်။

## အရေးကြီးသော တွေ့ရှိချက်များ

### ၁။ ဦးစားပေးအဆင့်မြင့် — အစစ်အမှန် transcript ကို ပြန်ဖွင့်ရာတွင် လက်ဗွေတန်ဖိုး မကိုက်ညီခြင်း

`mmnext/infrastructure/transcript_adapter.py` သည် transcript ဖိုင်ရေးသည့်အခါ fingerprint တွက်ချက်ရာ၌ အသုံးပြုထားသော `fingerprint_settings` ကိုပါ သိမ်းထားသည်။ သို့သော် `mmnext/ui/app_context.py` ရှိ ပြန်ဖွင့်စစ်ဆေးသည့် လုပ်ဆောင်ချက်သည် ဆက်တင်များမပါဘဲ fingerprint ကို ပြန်တွက်သည်။ ဆက်တင်များကို fingerprint တွင် ထည့်သွင်းတွက်ချက်ထားသဖြင့် တူညီသောတန်ဖိုးကို ပြန်မရနိုင်ဘဲ ဖိုင်ကို ပယ်ချသည်။ ဤအမှားကို အသစ်ပြုလုပ်ထားသော စမ်းသပ်ဖိုင်ဖြင့် ထပ်မံတွေ့ရှိခဲ့သည်။

အကျိုးဆက်အနေဖြင့် transcript ကို သိမ်းထားနိုင်သော်လည်း အသုံးပြုသူက အလုပ်စာရင်းမှ အဆိုပါအလုပ်ကို ပြန်ဖွင့်၍ မရနိုင်ပါ။ `_on_transcript_result()` သည်လည်း Job metadata အတွက် fingerprint ကို ဆက်တင်များမပါဘဲ တွက်ချက်၍ သိမ်းထားသည်။ စစ်ဆေးစာရင်း၏ §O–§P တွင်လည်း ယခင်က မှတ်တမ်းတင်ထားသော ပြဿနာဖြစ်သည်။

**အကြံပြုချက်:** ဖိုင်ထဲရှိ `fingerprint_settings`, `fingerprint_schema_version`, `fingerprint_source_type` နှင့် လုပ်ဆောင်မှုပုံစံတို့ကို မူရင်းဖိုင်ရေးစဉ်ကဲ့သို့ တူညီစွာ အသုံးပြုသည့် စစ်ဆေးနည်းတစ်ခုတည်းဖြင့် ပြန်လည်စစ်ဆေးရန်။ အစစ်အမှန် adapter ဖြင့် ထုတ်ထားသောဖိုင်ကို `AppContext` အသစ်မှ အလုပ်စာရင်းတစ်လျှောက် ပြန်ဖွင့်နိုင်ကြောင်း စမ်းသပ်ချက်ထည့်ရန်။ ဗားရှင်းဟောင်း သို့မဟုတ် မပြည့်စုံသောဖိုင်ကို ရှင်းလင်းစွာ ခွဲခြားပြရန်၊ နမူနာပုံစံသို့ တိတ်တဆိတ် ပြောင်းမသုံးရန်။

### ၂။ ဦးစားပေးအဆင့်မြင့် — ဖြန့်ချိတပ်ဆင်မှုစာရင်းတွင် package နှစ်ခု ပျောက်နေခြင်း

`pyproject.toml` ၏ `[tool.setuptools].packages` စာရင်းတွင် `mmnext.infrastructure.repository` နှင့် `mmnext.services.adapters` မပါဝင်ပါ။ စက်တွင်း မူရင်းဖိုင်တွဲမှ စမ်းသပ်သည့်အခါ စီမံကိန်း၏ မူလဖိုင်တွဲကို `sys.path` ထဲ ထည့်ထားသောကြောင့် ပြဿနာမပေါ်နိုင်ပါ။ သို့သော် wheel ထုတ်ခြင်း သို့မဟုတ် ပုံမှန် package အဖြစ် တပ်ဆင်ခြင်းတွင် လိုအပ်သည့် module များ မပါဝင်နိုင်သည့် အန္တရာယ်ရှိသည်။

**အကြံပြုချက်:** package နှစ်ခုကို ဖြန့်ချိမှုစာရင်းတွင် ထည့်ပြီး wheel တည်ဆောက်ပါ။ ထို့နောက် သန့်ရှင်းသော ယာယီ Python ပတ်ဝန်းကျင်တစ်ခုတွင် တပ်ဆင်ကာ လိုအပ်သော module များကို import လုပ်နိုင်ကြောင်း စမ်းသပ်ပါ။

### ၃။ ဦးစားပေးအဆင့်မြင့် — အမှန်တကယ်အသုံးပြုနိုင်သော လုပ်ငန်းစဉ် အကန့်အသတ်ရှိနေခြင်း

`AppContext` စတင်ချိန်တွင် `DemoMetadataService` နှင့် `DemoDownloadService` ကို အသုံးပြုသည်။ ထို့ကြောင့် Analyze/Download မျက်နှာပြင်များ ရှိနေခြင်းသည် YouTube အချက်အလက်ကို အမှန်တကယ်ရယူခြင်း သို့မဟုတ် ဗီဒီယိုကို အမှန်တကယ်ဒေါင်းလုဒ်လုပ်ခြင်းဟု မဆိုလိုပါ။ စက်တွင်းဗီဒီယိုမှ REAL transcript ရယူရန် အခြေခံရှိသော်လည်း ဘာသာပြန်ခြင်း/Gemini၊ Edge TTS၊ အသံပြန်သုံးသည့် cache၊ FFmpeg ဖြင့် နောက်ဆုံးဗီဒီယိုတင်ဆက်ထုတ်လုပ်ခြင်းတို့ မချိတ်ဆက်ရသေးပါ။ Common Editing, Splitter, Narrator, Exact Dubbing တို့၏ အမှန်တကယ် အထွက်လုပ်ငန်းစဉ်များနှင့် ဆက်တင်အားလုံးလည်း မပြီးစီးသေးပါ။

Exact Dubbing တွင် မူရင်းစာသား၊ အမှတ်အသားနှင့် အချိန်အမှတ်များ မပြောင်းလဲစေရန် စစ်ဆေးချက်များ ရှိသည်။ သို့သော် `workspace_screen.py` ရှိ Exact Dubbing panel မှ သိမ်းဆည်းရန်နှင့် စစ်ဆေးရန် ခလုတ်များသာ ချိတ်ထားပြီး တင်ဆက်ထုတ်လုပ်ရန် လုပ်ဆောင်ချက် မချိတ်ဆက်ရသေးပါ။ ထို့ကြောင့် အသံထပ်သွင်းခြင်း အပြီးသတ်ပြီးဟု မဖော်ပြရပါ။

### ၄။ ဦးစားပေးအဆင့်အလယ်အလတ် — Transcript ပြီးနောက် လက်ရှိအလုပ်စာရင်း ချက်ချင်းမပြောင်းလဲခြင်း

`AppContext._on_transcript_result()` သည် transcript အောင်မြင်ပြီးနောက် Job ကို disk ပေါ်ရှိ repository တွင် သိမ်းကာ transcript အခြေအနေကို `complete` ဟု ပြောင်းသည်။ သို့သော် ထို Job ကို လက်ရှိမှတ်ဉာဏ်အတွင်းရှိ `JobManager` ထဲသို့ ထည့်ခြင်း၊ အပ်ဒိတ်လုပ်ခြင်း သို့မဟုတ် `jobUpdated` signal ပေးပို့ခြင်း မတွေ့ရပါ။ App ကို နောက်တစ်ကြိမ်ဖွင့်သည့်အခါ အလုပ်ဟောင်းကို ပြန်ရှာတွေ့နိုင်သော်လည်း လက်ရှိဖွင့်ထားသော အလုပ်စာရင်းတွင် ချက်ချင်းမပေါ်နိုင်ပါ။

**အကြံပြုချက်:** သိမ်းဆည်းမှု အောင်မြင်ပြီးသည့်နောက် `JobManager` ကို အပ်ဒိတ်လုပ်ပြီး အလုပ်စာရင်းကို ပြန်ဆွဲရန် signal ပေးပို့ပါ။ Metadata ထဲရှိ `artifact_path` နှင့် `output_path` တို့၏ ရည်ရွယ်ချက်ကိုလည်း တစ်သမတ်တည်း သတ်မှတ်ပါ။

### ၅။ ဦးစားပေးအဆင့်အလယ်အလတ် — Transcript ပြန်ဖွင့်ခြင်းက မျက်နှာပြင်တုံ့ပြန်မှုကို ရပ်စေနိုင်ခြင်း

`JobsScreen._open_transcript_selected()` သည် `open_transcript_from_job()` ကို တိုက်ရိုက်ခေါ်သည်။ ထိုနည်းဖြင့် transcript ဖိုင်ကို ဖတ်ခြင်း၊ အကြောင်းအရာခွဲဖတ်ခြင်း၊ fingerprint နှင့် စာကြောင်းများကို စစ်ဆေးခြင်းတို့ကို မျက်နှာပြင်ထိန်းချုပ်သည့် အဓိက thread ပေါ်တွင် လုပ်ဆောင်သည်။ `AppContext.start_reopen_transcript()` နှင့် `ReopenTranscriptThread` နောက်ခံအလုပ်လုပ်စနစ် ရှိသော်လည်း အလုပ်စာရင်းရှိ ခလုတ်မှ ယင်းသို့ မချိတ်ဆက်ထားပါ။ transcript ကြီးပါက အက်ပ်မျက်နှာပြင် ခဏရပ်သွားနိုင်သည်။

**အကြံပြုချက်:** ဖိုင်ဖတ်ခြင်းနှင့် စစ်ဆေးခြင်းကို နောက်ခံ thread တွင် ပြုလုပ်ပါ။ စစ်ဆေးပြီးသောရလဒ်ကိုသာ မျက်နှာပြင်ထိန်းချုပ်သည့် thread သို့ ပြန်ပို့ပြီး session ကို အပ်ဒိတ်လုပ်ပါ။ စစ်ဆေးနေစဉ် အလုပ် သို့မဟုတ် အရင်းအမြစ်ပြောင်းသွားပါက ရလဒ်ဟောင်းကို မချိတ်ဆက်စေရန် ကာကွယ်မှုနှင့် အမှားပြသမှု စမ်းသပ်ချက်များ ထည့်ပါ။

### ၆။ ဦးစားပေးအဆင့်အလယ်အလတ် — ဖိုင်လမ်းကြောင်းအကန့်အသတ်ကို ထပ်စစ်ဆေးရန်လိုခြင်း

စစ်ဆေးစာရင်းအရ transcript ဖိုင်၏ လမ်းကြောင်းသည် သတ်မှတ်ထားသော Job ဖိုင်တွဲအတွင်းတွင်သာ ရှိကြောင်းနှင့် artifact ၏ mode သည် အလုပ်၏ mode နှင့် ကိုက်ညီကြောင်း စစ်ဆေးမှုများ မပြည့်စုံသေးပါ။ Metadata ပျက်စီးခြင်း သို့မဟုတ် မှားယွင်းဖွဲ့စည်းခြင်း ဖြစ်ပါက ဖိုင်လမ်းကြောင်း၏ နယ်နိမိတ်ကို ထပ်မံကာကွယ်ရန် လိုအပ်သည်။ ဤစစ်ဆေးမှုတွင် လမ်းကြောင်းကျော်ဝင်မှုကို တိုက်ခိုက်စမ်းသပ်၍ အတည်ပြုခဲ့ခြင်း မဟုတ်ပါ။ ထိုသို့မဖြစ်စေရန် ကြိုတင်ကာကွယ်မှု မပြည့်စုံသေးကြောင်းသာ မှတ်သားထားသည်။

**အကြံပြုချက်:** ဖြေရှင်းပြီးသော artifact လမ်းကြောင်းသည် သက်ဆိုင်ရာ Job ဖိုင်တွဲအတွင်းမှာသာ ရှိကြောင်း စစ်ပါ။ လုပ်ဆောင်မှုပုံစံ၊ ဖိုင်ဗားရှင်း၊ အရင်းအမြစ်၊ ထပ်မနေသော ID များ၊ မှန်ကန်ပြီး အချိန်အတိုင်းအတာအတွင်းရှိသော အချိန်တန်ဖိုးများနှင့် `is_demo=False` ဖြစ်မှုတို့ကို session မပြောင်းမီ အားလုံးစစ်ဆေးပါ။

## ကောင်းမွန်သောအချက်များနှင့် မူလစီမံကိန်းများနှင့် ကိုက်ညီမှု

- Domain နှင့် application အလွှာများသည် Qt ကို တိုက်ရိုက်မမှီခိုပါ။ Tkinter ကို မသုံးထားပါ။ UI ထဲသို့ legacy project အမည်များ မရောက်စေရန်၊ signal ချိတ်ဆက်ရာတွင် `self` ကို ဖမ်းယူထားသော lambda သို့မဟုတ် `partial` မသုံးစေရန် စမ်းသပ်စစ်ဆေးမှုများ ရှိသည်။
- နောက်ခံအလုပ်ဆောင်မှု၊ atomic ဖိုင်သိမ်းဆည်းမှု၊ Job သီးသန့်လမ်းကြောင်း၊ ပြန်လည်ရယူနိုင်သောအလုပ်များ ရှာဖွေမှုနှင့် တစ်သတ်မှတ်တည်းသော fingerprint စနစ်တို့၏ အခြေခံရှိသည်။
- Exact Dubbing အတွက် စာကြောင်းအရေအတွက်နှင့် အစဉ်၊ ID နှင့် မူရင်းစာသား၊ စတင်ချိန်နှင့် ကြာချိန်၊ မြန်မာစာနှင့် လိင်အမျိုးအစားတို့ကို စစ်ဆေးသည်။ Narrator နှင့် Exact Dubbing တို့၏ ပြင်ဆင်နေသောဒေတာကိုလည်း ခွဲထားသည်။
- `J:\movie-recap` ၏ Exact Dubbing လမ်းညွှန်နှင့် pipeline၊ `J:\recap-en-to-mm-main` ၏ recap planner၊ render worker၊ splitter နှင့် narration editor တို့ကို နှိုင်းယှဉ်ရာတွင် legacy စီမံကိန်းများ၌ အမှန်တကယ်ထုတ်လုပ်မှုစွမ်းရည် ပိုမိုပြည့်စုံနေသည်။ စီမံကိန်းအသစ်တွင် legacy ကုဒ်ကို UI/domain မှ တိုက်ရိုက်မခေါ်ဘဲ သီးခြား adapter နယ်နိမိတ်ထားရှိခြင်းမှာ သင့်လျော်သော ဦးတည်ချက်ဖြစ်သည်။ စစ်ဆေးမှုအတွင်း legacy စီမံကိန်းများကို မပြင်ခဲ့ပါ။
- `J:\movie-recap\SKILL.md` တွင် ထို Exact Dubbing လုပ်ငန်းစဉ်၌ NVIDIA သို့မဟုတ် အခြား chat API မသုံးရန် သတ်မှတ်ထားသည်။ ဤအစီရင်ခံစာသည် ထိုညွှန်ကြားချက်ကို မပြောင်းလဲပါ။ စီမံကိန်းအသစ်၏ စမ်းသပ်စစ်ဆေးမှုတွင်လည်း ပြင်ပ API client အချို့ကို တားမြစ်ထားသည်။

## အကြံပြုထားသော နောက်လုပ်ငန်းအစီအစဉ်

၁။ Adapter မှ အမှန်တကယ်ထုတ်ထားသော transcript ဖိုင်ကို ပြန်ဖွင့်ရာတွင် fingerprint ကိုက်ညီစေရန် ပြင်ဆင်ပြီး `AppContext` အသစ်နှင့် အလုပ်စာရင်းတစ်လျှောက် စမ်းသပ်ပါ။  
၂။ အလုပ်စာရင်းမှ transcript ပြန်ဖွင့်ခြင်းကို နောက်ခံ thread နှင့် ချိတ်ဆက်ပါ။ ဖိုင်စစ်ဆေးမှုကို နောက်ခံတွင်၊ မျက်နှာပြင်အပ်ဒိတ်ကို အဓိက thread တွင် လုပ်ဆောင်ပါ။ အလုပ်ဟောင်းရလဒ် မချိတ်ဆက်စေရန်နှင့် အမှားကို မြင်သာစေရန် ကာကွယ်မှု ထည့်ပါ။  
၃။ Transcript သိမ်းပြီးသည်နှင့် `JobManager` နှင့် အလုပ်စာရင်းကို အပ်ဒိတ်လုပ်ပါ။ Metadata အကွက်များ၏ အဓိပ္ပာယ်ကို တစ်သမတ်တည်းဖြစ်စေပါ။  
၄။ Setuptools package စာရင်းကို ပြင်ဆင်ပြီး wheel တည်ဆောက်မှုနှင့် သန့်ရှင်းသော ပတ်ဝန်းကျင်တွင် တပ်ဆင်၊ import လုပ်နိုင်မှုတို့ကို စမ်းသပ်ပါ။  
၅။ အထက်ပါအချက်များပြီးမှ ဒေါင်းလုဒ်၊ ဘာသာပြန်/TTS နှင့် လုပ်ဆောင်မှုပုံစံတစ်ခုချင်းစီ၏ render ကို တကယ့် adapter နှင့် သက်ဆိုင်ရာစမ်းသပ်ချက်များဖြင့် တစ်ဆင့်ချင်း ဆက်လက်တည်ဆောက်ပါ။

## နောက်ဆုံးအကဲဖြတ်ချက်

- **အင်ဂျင်နီယာအခြေခံ:** ကောင်းမွန်ပြီး စမ်းသပ်မှုစည်းကမ်းရှိသည်။
- **လက်ရှိအမှန်တကယ် လုပ်ငန်းစဉ်:** စက်တွင်းဗီဒီယိုမှ transcript ထုတ်ခြင်းအထိ အချို့လမ်းကြောင်းသာ အမှန်တကယ်ချိတ်ဆက်ထားသည်။ အခြားအဓိကလုပ်ဆောင်ချက်များမှာ နမူနာလုပ်ဆောင်မှု သို့မဟုတ် မချိတ်ဆက်ရသေးသော အခြေအနေဖြစ်သည်။
- **ထုတ်ဝေရန် အဆင်သင့်ဖြစ်မှု:** မပြည့်စုံသေးပါ။ Transcript ပြန်ဖွင့်ခြင်းနှင့် package ဖြန့်ချိမှုဆိုင်ရာ အတည်ပြုတွေ့ရှိချက်များကို ဦးစွာဖြေရှင်းရန် လိုအပ်သည်။
- **NVIDIA Nemotron စစ်ဆေးမှု:** မလုပ်ဆောင်နိုင်ခဲ့ပါ။ ဤအစီရင်ခံစာ၏ သုံးသပ်ချက်များသည် စီမံကိန်းကုဒ်၊ ယခု run လုပ်ခဲ့သော စမ်းသပ်ချက်များနှင့် လက်တွေ့ပြန်စမ်းသပ်မှုအပေါ် အခြေခံထားသည်။
